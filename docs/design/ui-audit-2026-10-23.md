# Workspace audit and integration history

Recorded on 2026-10-23. The original audit inspected the select/read/edit/share flow in fixture and native Codex views. This English summary retains decisions, causal findings, and verification limits. Historical native/reference screenshots were retired during OSS documentation cleanup; no fixture screenshot is presented as replacement native evidence.

## Layout findings

The first narrow detail view placed too many controls and property blocks before the body. Some presentation controls were difficult to identify. The wide workspace separated list, body, and properties, but duplicated repository/source controls and scattered actions across several locations.

The reorganization established a source/scope/search/list order, collected sorting and Project filters, moved utilities into Issue actions, and placed advanced properties behind a consistent disclosure. Wide views kept secondary properties beside the description; narrow views reflowed into one column.

Personal discovery began with Assigned to me. Created by me, Mentioned me, and All account repositories required explicit selection. An empty personal list did not silently widen. Repository suggestions were optional filters rather than a prerequisite for the personal view.

After the initial reorganization, 142 unit/adapter tests, 65-tool smoke, artifact checks, and 42 browser tests passed. These historical totals do not describe the current suite.

## Native observations and stale installed state

A native Codex view displayed the reorganized controls, retained the explicitly shared GitHub issue while another was browsed, and rendered authorized Linear issue content and authenticated images.

The account list initially failed because the running desktop server still had the old tool registry. Updating HTML did not refresh an already running server's tools. After restart, the registration/schema errors disappeared, the empty assigned list remained empty, an explicit broader scope displayed results, repository candidates loaded, and a native issue URL resolved correctly.

A new-chat draft operation returned host success, but the composer was not observed. A later send attempt timed out and was not retried; the record did not classify that ambiguous operation as success or failure.

## Picture-in-picture removal

Picture-in-picture was removed from Arco's product scope on 2026-10-23. The controls, dedicated rendering/styles, and resource declarations were removed; inline cards and the detail/workspace presentation remained.

Target-retention and Open details regression coverage moved to inline. If a fullscreen request was refused and the host returned inline, the UI kept the actual mode and displayed an error rather than claiming success. Native GitHub and Linear views confirmed removal of the old controls; fixture checks covered refusal and retry. The recorded step passed 44 browser cases in addition to the existing unit/build/smoke/artifact checks.

## Selection delivery and stale ranges

Native model-context receipt established whole-issue and body/comment selection delivery for GitHub and Linear at later points in the session. The source identity and selection origin matched in visible text and structured content. Selection payloads omitted the full body when only a passage was shared.

Before the successful GitHub comment check, releasing the pointer in comment whitespace could preserve the previous body range. A local reproduction failed for body-to-comment replacement, empty selection, and cross-container selection. Both providers were changed to validate ranges on content `mouseup`; the clear-only action was labeled Clear selection. Nine related browser cases and the existing build/unit/smoke/artifact checks then passed. The record did not assume this local cause proved the cause of every earlier native report.

Native verification was based on actual received payloads, not only success notices or screenshots. Composer mentions, inline return, and draft/send paths remained separate acceptance items at that stage.

## Selection controls

Provider multi-value properties adopted SDK multiple-select controls, preserving native IDs, existing unavailable selected values, and provider save behavior. Single-choice values stayed single-choice. Escape focus restoration and isolation from list keyboard shortcuts were tested.

The remaining dropdowns then moved to the shared `SingleSelect`, preserving groups/search, disabled options, clear values, native IDs, and same-value no-ops. Source values containing quotes or backslashes stayed unchanged despite internal SDK-safe IDs. Dialog portals and Escape handling were checked. The recorded step passed 53 browser scenarios and 142 unit/adapter cases.

Native appearance required restart confirmation because a newly opened tab could still load stale controls. A visual update alone did not establish successful interaction or provider persistence.

## Request-queue amplification

A native report showed `App server request queue is full` across settings, lists, details, properties, and reactions. Initial-load error UI also obscured already loaded content.

A fixture reproduction sent 26 size/theme notifications and increased tool calls from 11 to 205 before the fix. Code inspection linked visual notifications to broad data refresh, while canceled logical queries could leave old RPCs in flight. This demonstrated an amplification path; it was not a capture of the native host's actual notification stream.

The fix separated visual and data notifications, batched data refresh for 100 ms, limited refresh to the active provider, and avoided overlapping notification-driven refreshes. Tool/image RPC concurrency was limited to two, and writes were not automatically retried. Refresh failure retained loaded content and unsent drafts with a compact notice and Retry refresh.

After the fix, all 57 browser scenarios and 145 unit/adapter cases passed with the normal checks. In the limited fixture host, visual notifications added zero data reads, concurrency stayed at two or less, and an external issue update required one refresh. A subsequent native restart report said the problem no longer appeared; this was user-reported behavior, not measured native traffic.

Further regression checks used several viewports and repeated size/theme notifications. They preserved issue/draft state without sharing context, sending messages, or increasing settled tool-call counts. Pure display changes do not authorize provider writes or reset drafts.

## Contributor guidance

- Keep identity, reading, common actions, and advanced operations visually distinct.
- Distinguish browsing state, retained card target, and attached conversation context.
- Reopen/restart the host when verifying newly installed tools or resources; stale UI and stale server registration are independent concerns.
- Test theme/size/presentation notifications as visual events, not data-change events.
- Separate fixture success, installed-artifact identity, native display, model receipt, and provider persistence.
- Screenshots cannot certify contrast, screen-reader behavior, focus restoration, or complete keyboard reachability.
